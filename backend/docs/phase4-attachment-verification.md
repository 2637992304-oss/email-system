# 第四阶段附件功能验证记录

## 完成范围

| 任务 | 实现与验收依据 |
| --- | --- |
| 优化附件隔离存储 | 按上传用户、邮件和日期分目录，文件名使用 UUID；逐层校验目录并拒绝符号链接 |
| 补充下载权限校验 | 仅允许有效账号中的发件人或 `TO/CC/BCC` 收件人访问 |
| 修复附件联调问题 | 下载响应包含 MIME 类型、UTF-8 文件名和文件长度；数据库失败时清理孤立文件 |
| 验证正文附件分离 | 正文保存在 `mail.content`，磁盘保存附件内容，`attachment` 表仅保存元数据和相对路径 |

## 自动化验证

执行命令：

```powershell
cd backend
.\mvnw.cmd -Dtest=FileStorageUtilTest,AttachmentServiceTest test
```

覆盖场景：

- 同名或危险文件名经过清理后写入独立目录。
- `../` 和绝对路径被拒绝。
- 磁盘文件缺失时返回 404，错误消息不包含物理路径。
- 数据库写入失败时删除已保存的物理文件。
- 无邮件关系的用户下载时返回 403，且不会读取磁盘文件。
- 有权限用户通过校验后才能加载物理文件。
- 被禁用用户返回 401，且不会查询附件信息。

## 接口联调

`backend/api-tests/mail-module.http` 已包含以下手工联调请求：

- 发件人上传附件。
- 发件人查询附件列表。
- 收件人下载附件。
- 无关用户查询或下载附件时返回 403。
- 不存在的附件 ID 返回 404。

## 权限矩阵

| 当前用户 | 邮件关系 | 结果 |
| --- | --- | --- |
| 发件人 | 正常或在回收站 | 允许 |
| `TO/CC/BCC` 收件人 | 正常或在回收站 | 允许 |
| 收件人 | 已彻底删除邮件 | 拒绝 |
| 无关用户 | 无发件或收件关系 | 拒绝 |
| 未登录或账号禁用用户 | 任意 | 拒绝 |
