# 附件目录结构设计

## 设计目标

附件文件与邮件正文分离存储：邮件正文保存在 `mail.content`，附件物理文件保存在服务器磁盘，数据库 `attachment` 表只保存原始文件名、相对路径、大小、类型、上传人和所属邮件。

这样可以避免正文表被大文件拖慢，也便于后续做文件清理、迁移、备份和下载权限控制。

## 目录结构

建议配置附件根目录为应用外部路径，例如：

```text
data/uploads/attachments/
```

单个附件的相对路径格式：

```text
user-{uploaderId}/mail-{mailId}/yyyyMMdd/{uuid}-{safeFileName}
```

示例：

```text
data/uploads/attachments/
  user-1/
    mail-1001/
      20260528/
        8c8bbf6e-weekly-report.docx
        72a7d0c1-budget.xlsx
  user-2/
    mail-1002/
      20260528/
        31bf6a9d-project-plan.pdf
```

数据库中 `attachment.file_path` 保存相对路径，例如：

```text
user-1/mail-1001/20260528/8c8bbf6e-weekly-report.docx
```

业务代码下载时使用“附件根目录 + 相对路径”定位文件，不把服务器绝对路径返回给前端。

## 文件命名规则

上传时保留原始文件名到 `attachment.file_name`，实际磁盘文件名使用：

```text
{uuid}-{safeFileName}
```

规则：

| 项目 | 处理方式 |
| --- | --- |
| 唯一性 | 使用 UUID 或随机串作为文件名前缀 |
| 原始文件名 | 保存到数据库 `file_name`，用于页面展示和下载响应头 |
| 安全文件名 | 去掉路径分隔符、控制字符等危险字符 |
| 路径保存 | 数据库只保存相对路径，不保存绝对路径 |
| 覆盖风险 | 即使两个用户上传同名文件，也会落到不同目录或不同 UUID 文件名 |

## 权限控制

附件下载接口建议为：

```text
GET /api/attachment/download/{id}
```

下载前需要校验：

| 校验项 | 规则 |
| --- | --- |
| 附件存在 | `attachment_id` 必须能查到记录 |
| 文件存在 | `file_path` 对应的磁盘文件必须存在 |
| 用户已登录 | 从 Token 中取得当前用户ID |
| 用户有权访问 | 当前用户是发件人，或存在对应 `mail_receiver` 收件记录 |
| 路径安全 | 根据根目录解析最终路径，确认最终路径仍位于附件根目录下 |

如果校验失败，应返回明确错误信息，但不要暴露服务器绝对路径。

当前实现的访问规则：

- 发件人可以查看和下载自己发送邮件的附件，包括邮件位于发件人回收站时。
- `TO`、`CC`、`BCC` 收件人均可查看和下载附件，包括邮件位于收件人回收站时。
- 收件人彻底删除邮件后，`mail_receiver` 关系被删除，因此不再具有下载权限。
- 与邮件无关的用户、被禁用用户以及未登录用户不能读取附件元数据或物理文件。

## 与邮件流程的配合

阶段二先确定数据和目录设计，阶段三开发接口时按以下流程落地：

1. 写邮件页面上传附件。
2. 后端保存文件到隔离目录。
3. 后端写入 `attachment` 元数据。
4. 邮件发送成功后，`attachment.mail_id` 与 `mail.mail_id` 绑定。
5. 收件人进入邮件详情页，根据 `mail_id` 查询附件列表。
6. 下载附件时按当前用户与邮件关系做权限校验。

## 异常场景

| 场景 | 处理建议 |
| --- | --- |
| 附件ID不存在 | 返回 404 或业务错误码 |
| 磁盘文件缺失 | 返回“附件文件不存在或已被清理” |
| 用户无权限 | 返回 403 |
| 文件名包含路径符号 | 上传时清理文件名，只保留安全名称 |
| 邮件删除 | 级联删除附件元数据，物理文件由定时任务或业务代码清理 |

## 第四阶段加固结果

- 存储目录按 `user/mail/date` 隔离，磁盘文件使用 UUID 前缀避免同名覆盖。
- 数据库仅保存相对路径，接口不返回服务器绝对路径。
- 目录创建时逐层拒绝符号链接和非目录节点，读取时同时校验规范化路径和真实路径。
- 下载前先校验登录用户、账号状态、邮件状态以及发件/收件关系。
- 数据库写入失败时补偿删除已写入的物理文件，避免产生无元数据的孤立附件。
- 磁盘文件丢失时统一返回 404，不在错误信息中暴露服务器目录。
